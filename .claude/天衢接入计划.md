# 天衢「一句话接入」实施计划

## 目标
让接入方不敲一行代码，通过一句话即可完成天衢框架的接入与功能使用。
当用户提出天衢不支持的功能时，系统能明确拒绝，不修改任何文件。

## 实现方式
**Claude Code Skill + 本地 stdio MCP Server（Kotlin Fat JAR）**

---

## 架构
```
用户一句话
    ↓
.claude/skills/tianqu/SKILL.md ← Skill：理解意图 + 强制执行 SOP
    ↓
tianqu-mcp-server（本地 JAR）   ← 暴露 3 个核心工具
    ├── tianqu_get_capabilities      → 天衢能力清单 & 不支持边界
    ├── tianqu_analyze_project       → 扫描接入方工程模块结构
    └── tianqu_get_integration_guide → 按模块类型返回精确接入指令
    ↓
Claude Code 自身                ← 修改 Gradle、生成代码、补充注释
```

## Skill 工作流 SOP
1. 调用 `tianqu_get_capabilities` 验证需求是否在支持范围内，否则直接拒绝
2. 调用 `tianqu_analyze_project` 扫描当前工程结构
3. 调用 `tianqu_get_integration_guide` 获取精确改动清单
4. 执行改动，生成的代码需包含必要注释帮助接入方理解

## 接入方使用方式
1. 将打包好的 `tianqu-mcp-server-all.jar` 放入项目根目录下的 `mcp-servers/` 等任意目录中
2. 在项目 `.claude/settings.json` 中注册（推荐使用相对路径以支持团队共享）：
```json
{
  "mcpServers": {
    "tianqu": {
      "command": "java",
      "args": ["-jar", "mcp-servers/tianqu-mcp-server-all.jar"]
    }
  }
}
```
3. 将 `.claude/skills/tianqu/SKILL.md` 按此目录结构放入项目 `.claude/skills/tianqu/` 目录
4. 对 Claude Code 说："帮我接入天衢框架"即可

## 常见问题排查

### `/mcp` 命令看不到 `tianqu` 服务

**现象**：项目里已有 `.claude/settings.json` 且配置了 `tianqu`，但在 Claude Code 中执行 `/mcp` 仍显示无 MCP 服务。

**原因**：Claude Code 会在本机全局文件 `~/.claude.json` 中缓存每个项目的 MCP 配置状态。如果该项目在配置 MCP 之前就被打开过，缓存中会记录空的 `mcpServers: {}`，这个缓存会覆盖项目内的 `.claude/settings.json`。

**解决方式（二选一）**：

方式 A（推荐）：重启 Claude Code，再重新打开该项目，Claude Code 重新初始化时会优先读取 `.claude/settings.json`。

方式 B（手动修复）：直接编辑 `~/.claude.json`，找到该项目路径对应的 `mcpServers` 字段，改为：
```json
"mcpServers": {
  "tianqu": {
    "command": "java",
    "args": ["-jar", "mcp-servers/tianqu-mcp-server-all.jar"]
  }
}
```
